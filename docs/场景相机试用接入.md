## 试用行为

识别网格时优先尝试活动场景相机。新来源通过检查并有可用几何时，打开现有临时相机选择器，把“场景相机·试用”放在首项，显示网格预览。检查地砖贴合后点击“本次采用”。预览期间不启用吸附、染色或落笔；采用后复制当前显示几何并按既有规则保留本次会话网格。

旧的后台线程栈扫描、完整相机校验、自动采用规则和手动恢复仍保留。新来源的签名、场景身份、姿态或投影失败时继续原流程；旧来源缺少角色高度、自动平面无效或自动交付超过 250ms 时，也先检查本请求已捕获的可用手动候选。只要任一路径能显示网格，就交付预览，不以其中一路的失败覆盖成功结果。共享的关卡/manager/输出上下文失效时，两种来源都不能视为当前有效网格。

选择器中的“使用原方案”关闭当前预览并发起一次优先使用原方案的请求。新来源仍会采集；旧方案没有可用结果时由场景相机兜底，避免单一路径失败就报错。此优先顺序只作用于本次请求，不保存为偏好。它是主动重新定位，会按既有规则放弃旧网格 pin/backup，保留屏幕标注。

本次采用手动确认作为试用入口，不把新来源的试用投影自动升级为可信网格。候选待确认与可用网格方向待确认均显示普通提示，后台 Preview 的 error=None；不会触发新的错误汇报入口，也不写 Game grid unavailable。SS-GRID-015 保留解释历史日志，不再为当前可用预览发出。原错误汇报快照和独立的版本兼容警告仍保留。不恢复 SS-GRID-012 的采用重校验门。

## 实现与边界

- `scene_camera.cpp` 从 PE `.text` 唯一特征解码活动 manager 槽及 position/orientation/projection/cameras 偏移。交叉检查更新分支、相机列表、冻结分支、渲染参数和活动场景引用，保存六段完整代码字节。当前只支持 `retail-r13-2026-10-17b` 形态；活动根还必须与 StarSketch 现有 r67271 根一致。
- 所有读取使用现有受保护的读内存路径。验证 native mode=0、相机列表数量、每个 `Camera_Control` 的 owner/ID/类型/尺寸/未销毁状态，前后复核列表、对象与代码证据。姿态连续读取两次且完全一致，并检查有限值、位置范围、单位四元数和 FOV/near/far。读取和扫描都在既有串行后台 worker 中完成；不增加渲染线程扫描、玩法写入、冻结相机或卸载等待。
- 按游戏 +X 前、+Y 左、+Z 上的约定构造完整 view 和反向深度透视 projection，复用 StarSketch 的平面单应映射；不把视角四舍五入为正交轴，也不以等距网格替代透视。输出尺寸仍是最终 swapchain 画布。
- **新来源独立读取当前活动场景姿态，不再要求栈旁证才能预览。** 重新核对上游 HEAD 仍为 `cf432e95962b946c80a9e6fdea6dba307dc757c9`：`game_camera_snapshot` 通过代码/场景/相机实体身份和 pose 检查直接读取 manager，不依赖线程栈帧。此前 StarSketch 额外加的 type=8 门槛使两种方案共用同一故障点，本次按用户要求去掉这一手动预览门槛。原栈验证器不变。
- type=8 现在只提供可选旁证，仍按原姿态关联、视口、map_amount 0..0.05 和前一轮最新帧推进检查记录 `corroborated`。原栈静态旧副本仍不能当作新帧。新来源的 CameraFrame 保持空，不伪造帧号、时间或地图状态；实时 double-read 的 manager pose 与栈新帧是两种不同证据。地址最多 512 个，仅本请求有效。
- **独立姿态不等于已验证最终画面。** 新来源没有独立读取 engine 帧号/地图混合状态；普通 native mode=0、稳定关卡和有效 pose 可生成预览，但地图/过场画面可能不贴合。选择器提示在普通游戏视角检查，必要时返回后刷新。可用几何只进入手动确认，不自动吸附/染色，不声称已修复所有机器的主视图问题。
- 新来源不持久化布局地址、相机姿态、候选、翻转、高度或几何。采用、取消恢复旧网格、关闭/重开、不可用关卡暂停、切关与尺寸变化清除规则均沿用当前实现。

诊断记录 `scene_camera` 的 profile、状态、读取/匹配/新帧计数、预览有无、可选 `corroborated`、`stack_required=0` 和来源优先顺序；不输出姿态或矩阵。预览使用普通 Camera preview 日志，真正失败仍保留稳定错误编号。手动采用日志记录 `source=scene_pose` 或 `source=stack`。一键复制诊断包含本次 marker。

## 此前 SS-GRID-013 复查 — 2026-10-29（历史阶段）

用户确认集中报错的是公开 0.2.2。核对公开提交 `969109a8062f587c072329539d3fab4fcba8464b`：自动等待结束时，即使请求内已经收集到可手动显示的辅助候选，也直接返回 SS-GRID-013。它尚不包含本地后台采样、超时转预览恢复或场景相机来源。这解释了公开版与当前试用包的行为差异；不能由此认定所有报告具有相同的主相机损坏原因。

本地复查修正了以下遗漏，构建另标记 `camera preview selfcheck 20261029`：

- 原栈候选的自动恢复预览尊重用户明确指定的高度，不再被角色建议层替换。未指定自动高度及手动选择器仍优先建议角色层；该层不能生成可用几何时，尝试当前传入的备用高度，且仍须通过原几何检查。新场景来源使用相同的备用高度规则，不遍历或猜测高度。
- 选择器采集期间，新来源已通过初始新帧/身份/地图检查的快照，不再因后续一次姿态不稳定、读失败等被清掉，与原栈候选的快照行为一致。取消或新请求清除候选，交付仍检查关卡/manager；不会把后续坏读取写入旧快照，也不恢复采用时重校验。
- `recovery` 诊断新增 `geometry_rejected` 与 `height_fallbacks` 计数，帮助区分“采到了辅助帧但投影不可用”和“已有可确认预览”。没有可用几何时仍保留 SS-GRID-013；不会为消除错误强行启用反射或空网格。

该阶段仍依赖 type=8 栈旁证；最新独立兜底已由上文替代。后续实机应核对启动标记、候选来源和实际贴合情况。

# 手动网格校准工具评估

日期：2026-10-26。基于当前代码与隔离数值/UI 回归；没有取得受影响玩家的校准操作录像或进行新的游戏实测。

后续状态：用户已要求以临时相机选择替代四点。当前运行时已移除三点/四点、选点状态和四点说明窗，Shift+G 改为 [临时选择相机](临时相机选择说明.md)。下文保留此前校准局限及替代路线的历史分析。

## 结论

用户随后明确要求删除三点、四点不再输入行列数，并评估选择相机及跨关卡复用。当前本地代码已删除三点入口、模式和实现；四点改为同一格四角、拖点预览、显式采用，不再要求整关卡外框或行列数。方向预览与偏好保存保留。[相机列表与跨关卡匹配评估](相机列表与跨关卡匹配评估.md)建议把候选选择作为主要恢复方式，当前尚未实施相机列表或特征学习。

## 原有工具的能力和限制

| 工具 | 实际实现 | 为什么可能无法恢复正常 | 建议 |
| --- | --- | --- | --- |
| 快速三点 | 点击中心和两个相邻中心，构造 origin/u/v，px=py=0 | 只有仿射变换，格距不随远近变化；斜俯视下只能局部对齐，不能修复透视 | 已删除，不再保留高级入口 |
| 原四点透视 | 输入整块棋盘行列数，按左上、右上、右下、左下点击外边界，求解平面单应映射 | 默认 8×7 容易与实际不符；格子中心与外边界混淆会产生半格偏移；不规则边缘、遮挡、多高度层让整板外角难以定义；点选后没有拖点、撤回单点或实时整网格预览 | 保留求解器，已替换整板外框及行列数交互 |

四点模型已经有外角回投、格点正反变换与透视格距回归。它能表达平面透视，不能从未知的点击意图自动判断棋盘真实边界或格数，也不能用一个平面同时贴合不同高度的格子。现有证据不支持“四点数学模型整体无效”的结论。

这两项是重新建立屏幕网格，不是调整相机方向的工具。原来的方向失败会暂停自动结果；手动校准需要完整重建自己的网格，因此用它修复一个本来只需翻转的结果，步骤过多且易引入新的半格、比例误差。

## 当前四点回退及后续主流程

1. 当前选择同一格四角，固定为一个格子的单位对应关系，不再指定行列数或跨格间隔。
2. 四个点可拖动；支持撤回一点、重选和取消。显示完整网格预览，检查近端和远端；无效四边形保留点以便修正，不清空重来。
3. 用户点击“采用网格”后启用吸附和染色，已有标注不随网格移动。校准只在当前会话有效。
4. 单格的鼠标像素误差会在远端放大，因此这项改动降低操作负担，不证明相机或远端贴合已经修好。四个任意角本身不包含格距信息；若不提供相机/图像间距等额外信息，也不限制为同一单位格，就无法唯一确定网格密度。
5. 建议将候选相机选择和有限特征偏好作为主要恢复路径，让用户预览选择后无需手工计数；四点保留为完全没有可用候选时的独立回退。

底层仍使用一般平面单应映射，当前 UI 以一个格子的四边界建立对应关系。鼠标点选、拖点、无效点序、取消和显式采用已经有 UI 回归；尚缺受影响玩家的实际贴合验证。没有加入图像格距推断或自动跨关卡匹配。

## 本次方向功能的范围

- 方向以外的数值、矩阵、视口、地图、新帧、关卡及投影可用性检查仍生效。正常候选在同次 poll 中优先于方向异常候选，不因异常候选帧号较大而优先选它。
- 只有方向校验失败且通过其余检查的新帧可以生成候选预览。首次遇到该类方向时，显示 SS-GRID-011 提示；确认前不吸附、不染色。
- 上下/左右翻转围绕完整输出画布作用于全部透视系数，不是简单反转网格轴。可恢复原始方向并重新确认。
- 仅保存用户确认的方向选项，按原始方向判据的类别区分，避免正常相机继承镜像候选的设置。类别是 direction_z、handedness、world_up 三个方向判据的位组合，不是主视图身份凭证。
- 方向偏好写入原 settings.ini；不保存任何标注、相机矩阵或校准几何。相同类别重入/重启后可复用偏好，但不证明数据来源正确；若位置、格距、透视仍错，应重新识别或校准。
- 011 仍可能表示扫描曾遇到方向异常但最终没有拿到可用新帧；只有错误编号、没有可用候选时，不能凭空显示网格。

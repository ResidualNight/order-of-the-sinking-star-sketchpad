# 后台相机采样修复

日期：2026-10-29（Asia/Shanghai）。本地 0.2.2 修复，不替换公开 `v0.2.2-test` 附件。

本文记录先完成的后台采样修复。随后用户明确要求“适当放宽识别条件，有网格总比报错好”；手动候选和自动失败后的预览行为已按 [候选网格预览恢复](候选网格预览恢复.md) 调整，本文“保持全部校验”的描述仅对应先前阶段，完整自动确认仍沿用原阈值。

## 本次日志能确认的问题

用户提供的追加日志包含旧 0.1.2、0.2.0、0.2.1 和最后一次 0.2.2 运行，应按启动段分别分析。最后一段包含 `camera capture fix 20261027`，不是未更新的旧包。

最后一段在 3840×2160 输出下有六组 SS-GRID-013：关卡结构校验成功，线程栈扫描/读取没有失败；每组都捕获到大量通过新帧校验的 type=5 反射视图，尺寸约 960×540、方向类别 3。type=8 主视图样本尺寸约 3840×2160、方向正常，变换逆误差约 1.5e-5 至 3.1e-5，但投影逆误差稳定为 1，必须继续拒绝。其余结构近似副本还有 NaN 或异常大数，同样不能采用。

临时选择器取得了 9 个候选，日志没有记录采用；不能由候选数量推断它们都是独立相机、存在正确主视图或玩家已验证贴合。最后一组时间回退发生在关卡变化附近，但后续仍有 197 次新帧通过；它不能解释全部六组失败。

因此可确认直接失败原因是“自动路径只取得合格的辅助视图”，不是栈读取权限、输出尺寸或游戏哈希门。日志不含完整矩阵，不能确定主视图副本何时、由谁覆盖，也不能直接重建一份正确主相机。

## 采样路径修复

此前自动识别和候选收集都只在 Present 叠加层调用期间运行。即使先于 ImGui/DX12 读取，也仍落在每帧的相同阶段，且扫描本身会在调用线程上执行其他函数。2026-10-27 的外部只读调研曾在同版本普通游戏视角取得完整、更新中的主视图；这支持调查采样时机，但不能代替本次受影响机器的复测。

新 `GameGridWorker` 将现有读取器放到独立后台线程：定位约 1.8 秒、临时收集约 1.2 秒内，候选轮询延迟循环使用 3/4/5ms，最多每 50ms 重扫线程栈。当前采样线程的栈被排除，数据和观察记录在堆上。请求结束后线程退出；取消/刷新只设置取消标志并替换待处理请求，一个服务最多运行一个采样线程，不在绘制线程等待扫描完成。线程持有 DLL 引用至内部对象释放后退出；全局对象析构只设置原子取消标志，不在 DLL 卸载/进程退出时获取工作线程的锁或等待线程。

界面发起时绑定经过 guarded read 校验的关卡身份和管理器。后台开始、采样期间以及结果交付时都检查上下文；替换、关闭、尺寸变化或取消请求后，不交付旧任务结果。自动捕获在交付时仍不得超过 250ms。扫描和轮询均沿用原数值、两组逆矩阵、视口、方向、地图、用途、新帧及投影检查，保留最多 512 条请求内观察记录和有限标量证据。不修补不完整矩阵，不自动采用 type=5，不把 type=8 当作放行条件。

临时选择器仍只收集通过原初始数据/新帧校验的预览；一旦显示，玩家“本次采用”继续直接接受显示的可用几何，不增加来源复读、采用时新帧检查或 SS-GRID-012 阻断。会话固定网格、取消恢复、加载暂停和几何不持久化的行为保持。

启动标记为 `background camera sampling 20261029`；成功和失败日志包含 `sampling=background`。新登记 SS-GRID-014 用于采样任务启动/运行失败，创建线程失败附 Win32 错误值。

## 验证范围

新增隔离回归使用生产后台线程、实际线程栈发现和 guarded reads：主视图仅在两次界面轮询之间短暂完整，下一次界面轮询时投影逆已损坏，后台仍须取得此前完整的新帧。另覆盖超过 250ms 的自动交付拒绝、结果交付前关卡变化、临时预览保留、快速请求替换、取消和反射只手动。全部使用构造数据，不启动或读取真实游戏。

这修复了代码中只能在固定绘制阶段采样的缺口；尚不能宣称已确认受影响电脑的覆盖来源或游戏内网格贴合。需使用新启动标记在该电脑复测。公开附件保持不变，新 DLL 未安装到真实游戏。

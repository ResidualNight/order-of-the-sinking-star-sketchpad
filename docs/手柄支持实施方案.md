## 首版支持范围

| 输入来源 | 首版目标 |
| --- | --- |
| Xbox 原生 XInput，Steam Input 关闭 | 正式验收目标 |
| Xbox 或其他手柄，经 Steam 模拟 Xbox 输出 | 正式验收目标；读取 Steam 映射后的状态 |
| Steam 纯键鼠模拟 | 沿用键鼠路径，关闭新增手柄动作，作为单独兼容模式测试 |
| Steam 同时输出手柄和键鼠的混合布局 | 诊断、提示和配置指引；不承诺任意布局自动去重 |
| 非 Xbox 手柄直接使用 DirectInput/HID | 暂不直接支持，使用 Steam 的 Xbox 模拟 |
| 原生 Steam Input 动作接口、陀螺仪、震动、设备专属图标 | 后续独立评估 |

Steam 官方说明，其 Windows 手柄模拟会挂接 XInput 等接口并提供模拟 Xbox 输入；它也支持键鼠模拟和原生 Steam Input API。因而以 XInput 覆盖前两类有依据，但“从 Steam 启动”本身不能确定输入路径。[Valve 官方说明](https://partner.steamgames.com/doc/features/steam_controller/steam_input_gamepad_emulation_bestpractices)

设置区区分“XInput 手柄”和“Steam 键鼠模拟”，不以按钮时间接近就判定同源。检测到鼠标活动也不能可靠判断来自真实鼠标还是 Steam 模拟。首版建议使用纯手柄布局；未知混合布局应显示兼容限制，不自动改写玩家的 Steam 配置。

## 交互方案（2026-11-08 Preview 5）

用户提供默认游戏按键图：View 为重新开始，Menu 为菜单，L3 为俯视图，R3 为区域视图；其余肩键、扳机、ABXY、方向键、摇杆轴也已有用途。撤销旧方案的 View + Menu 候选，不能称任何普通单键完全空闲。

### 入口：LT + RT 同时按下

按用户选择，使用两个扳机，取消 L3/R3 入口。两侧在 180ms 配对窗口内达到 160/255 即开启，不要求额外长按。进入后先松开扳机和其他控件才接受绘图，组合触发时先在游戏查询层隔离全部槽位，再打开 UI。

原游戏两个扳机各有动作，因此在查询层缓存组件：单扳机增加约 180ms 延迟，未配对按原顺序补交模拟量变化，短按和快速重复不丢失。其他分量不随配对等待冻结。设置明确说明延迟，并允许关闭双扳机入口，保留键盘 E。首版未实现自定义手柄入口改绑。

状态只由实际游戏新鲜查询推进，不使用 SendInput。失焦取消待开启请求，隔离退出逐分量等待释放。普通游戏从未进入隔离时的断连重连保持透传；实际隔离后的重连保留释放屏障。有限缓存耗尽时放行，不能无限阻塞游戏。上述行为已有自动测试，实际游戏时间控制是否完全无副作用仍待用户验证。
不把 Xbox/Home 或 Share 当作通用默认入口：当前 XInput 标准状态未提供这些按钮。自定义 Steam 键鼠映射作为单独可选配置，不自动修改玩家 Steam 配置。

### 界面选择：按打开方式自动选择，加手动锁定

设置增加“界面模式”：自动（默认）、固定键鼠、固定手柄。键鼠界面与手柄设置页都能调整，不要求先使用鼠标完成初始化。

- 自动模式：通过 E/键鼠入口打开时显示键鼠布局，通过手柄入口打开时显示手柄布局。
- 连接手柄仅影响设备状态与入口提示，不立即切换 UI，不因摇杆漂移或 Steam 生成鼠标事件改变布局。
- 本次打开期间固定布局；通过明确的切换操作才能更换。切换时结束/取消当前手势，等待确认键/扳机释放，再转移操作归属。按下切换的同一事件不能同时落笔或确认。
- 界面偏好与设备是否允许输入分开。固定手柄布局仍保留鼠标作为恢复途径，插拔不清除绘图。有效画布状态、历史、当前工具/色板共享，菜单焦点与虚拟光标各自保存为会话状态。
- 只有入口发起控制器操作草稿纸，其他控制器不抢焦点；游戏侧沿用全部受支持槽位隔离。断线结束当前手势并提示重新连接或键鼠接管，不能仍按绘图状态恢复。

这是有边界的自动选择，不是持续追踪“最后输入设备”而随时重排布局。

### UI：画布操作与菜单焦点分开

手柄绘图区保持中央棋盘可见；底部是一行大尺寸工具卡（画笔、箭头、星标、编号、橡皮）及当前颜色、宽度/大小。附近显示当前可用按键提示。网格状态放在小型状态条。按 A 打开快捷面板，包含色板、画笔属性、吸附与染色；Menu 打开完整设置。相机选择和网格精调使用同一套可聚焦列表、选项卡和步进控件，不要求摇杆点击小复选框。

画布以虚拟光标定位；菜单使用方向焦点。两者是互斥状态：进入面板就冻结画布光标并结束/取消手势，返回时恢复原位置且等待扳机释放。数值控制左右步进、长按连调，颜色优先使用现有色板及可聚焦通道编辑，避免必要操作依赖鼠标拖动。明确的焦点边框与当前按键提示须在小分辨率、宽屏和电视距离可读。

| 控件 | 画布状态 | 菜单状态 |
| --- | --- | --- |
| 左摇杆 | 移动光标，死区与速度曲线 | 移动焦点 |
| 右摇杆 | 低速精调光标，右杆有效时优先于左杆 | 滚动列表/说明 |
| 方向键 | 已确认网格按屏幕方向选相邻格；否则小步移动 | 移动焦点/已进入控件时调值 |
| RT | 当前工具绘制/放置 | 不落笔 |
| LT | 临时擦除 | 不擦除 |
| LB/RB | 上一个/下一个工具 | 上一页/下一页（无分页时不操作） |
| A | 打开快捷面板 | 确认/进入控件 |
| B | 取消未提交手势；空闲时退出草稿纸 | 退出控件或关闭最上层面板，一次只退一层 |
| Y / X | Y 撤销；长按 X 轮盘 | 不修改画布历史，不呼出轮盘 |
| Menu | 打开设置 | 关闭设置（先处理编辑中的控件） |

建议默认星标或上次工具，降低首次操作门槛。星标和单个编号按一下 RT 放置；箭头两次 RT 选起点/终点，有实时预览，B 取消未提交箭头；画笔按住 RT 移动，松开结束；橡皮/LT 一次连续擦除合并为一次撤销。保留网格上按住 RT 连续编号能力，以不同格为落点，不因帧数或重复采样产生多个编号。手柄无网格时不承诺逐格操作。网格相邻格选择要结合屏幕投影，避免方向键与画面方向相反。

已提交编号和擦除不因 B 静默回滚，撤销交给 Y。清空置于菜单并二次确认；重启编号单独明确操作，不混入退出或改色。改变工具或进入菜单时先处理当前手势；RT 在画布开始后不会变成控件点击，菜单确认也不会穿透画布。所有 UI 复用现有绘图和历史模型，不新建一套独立草稿数据。

### 实施顺序与剩余验收

1. 先完成入口候选识别与组件消费，验证游戏视图不被切换、单键仍可用、退出无动作残留。
2. 实现界面模式偏好、会话状态与手柄画布基础操作，优先星标/编号/箭头、撤销重做。
3. 完成快捷面板及设置、相机选择、网格精调焦点导航，然后补自由绘图手感和各尺寸布局。
4. 按原生 Xbox / Steam XInput 两条路径实测；纯键鼠模拟及混合映射单独记录，不把当前实机成功扩大为所有配置兼容。

设计依据：当前项目输入桥及 UI/历史语义、用户默认键位截图。微软的[手柄交互指导](https://learn.microsoft.com/en-us/windows/uwp/ui-input/gamepad-and-remote-interactions)区分方向焦点导航与适合绘画的自由指针；[XINPUT_GAMEPAD](https://learn.microsoft.com/en-us/windows/win32/api/xinput/ns-xinput-xinput_gamepad)列出当前标准按钮范围。本节具体映射与切换规则为项目设计建议，并非平台硬性要求。
## 技术拆分

建议在分支内新增小模块，避免把所有状态塞入 native.cpp。下列名称是实施建议，不代表已创建文件。

| 模块 | 责任 |
| --- | --- |
| gamepad_input.hpp/cpp | 动态 XInput 接入、0–3 槽位探测、控制器选择、标准化快照 |
| gamepad_capture.hpp/cpp | 实际游戏读取路径挂接、隔离与恢复、线程安全快照和防递归 |
| input_router.hpp/cpp | 键鼠/手柄动作合并、优先级、边沿、扳机迟滞、组合消费 |
| virtual_pointer.hpp | 时间缩放、死区、速度、边界限制、滚动和慢速模式 |
| native.cpp | 生命周期与帧接线；保证虚拟事件不被 Win32 后端覆盖 |
| ui.cpp / ui.hpp | 共用动作执行入口、画布手势归属、控件可达性和手柄提示 |

XInput 支持槽位 0–3；连接设备每帧采样，空槽按低频探测。由触发入口的控制器成为当前设备，允许显式选择，不合并多只手柄的按钮。[微软 XInput 说明](https://learn.microsoft.com/en-us/windows/win32/xinput/getting-started-with-xinput)

### 输入隔离

实际数据流为：原生设备或 Steam 映射 → 保留原有调用链的采样 → 草稿纸输入；游戏读取经过单独过滤，在绘画期间得到中立按键/摇杆/扳机。

实施顺序：

1. 记录实际加载的 XInput 模块、游戏查询入口和初始化时序，判断是否还有其他输入通道。只保留有限诊断，不记录连续用户输入、原始内存或游戏数据。
2. 优先包装可确认的游戏侧查询入口或函数指针。若必须挂接函数入口，使用明确兼容、可回退的方案；处理已经缓存的函数指针，不能只在首次打开 UI 后拦截 GetProcAddress。
3. 草稿纸读取必须保留 Steam 转换结果，游戏读取才归零。不能盲目跳过 Steam 的挂接，也不能将我们自己的采样一起屏蔽。
4. 中立状态保留正常连接语义，处理 packet number 在进入/退出隔离时的变化，避免游戏缓存旧的按住状态。若游戏使用按键事件等其他查询接口，须同步处理其残留事件。
5. 绘画时屏蔽所有可能驱动当前游戏的手柄槽位，但仅选中的槽位控制草稿纸。不同槽位分别维护释放状态。
6. 不采用全局关闭 XInput、不另放一套 XInput 代理 DLL、不在 DllMain 中扫描/等待，不破坏现有 DXGI 安装方式。
7. 采样和游戏查询可能来自不同线程。过滤回调只读取轻量快照，不获取渲染锁、不运行 ImGui、不执行 IO；失效时退出手柄会话并恢复透传，保留键鼠功能。

Probe 4 已补上本机构建的提前缓存路径，用户已确认输入识别与退出后移动恢复；跨 Steam 配置及多设备覆盖仍待验证。独立测试程序只能验证接口封装；必须在游戏进程及 Steam 环境里验证最终隔离。

### 光标与生命周期

速度按时间和输出尺度归一化，限制异常帧间隔造成的跳跃；保留亚像素累积，输出位置夹在当前画布内。以归一化位置跨分辨率转换，再处理已有的 resize 取消手势逻辑。横纵速度使用同一尺度，避免超宽屏上的斜向失真；设置可调速度和慢速比例。

先统一真实鼠标和虚拟光标的事件来源，再将最终事件送入 ImGui。注意 Win32 NewFrame 会更新鼠标位置，旧消息和默认 XInput 后端也可能加入事件；实施时由单一输入桥决定顺序，不能仅在一帧末尾修改 MousePos。手柄路径不发送系统级模拟鼠标或按键。

| 状态 | 行为 |
| --- | --- |
| 游戏操作 | 原样透传，监测入口；仅在采用组合延迟方案时影响候选按钮 |
| 进入绘画 | 隔离游戏输入，初始化虚拟光标，等入口和绘图按钮释放 |
| 绘画或界面交互 | 路由到唯一消费者，持续隔离游戏 |
| 退出等待释放 | 只拦截退出时仍按住/偏转的分量，其他输入立即恢复；回中/释放后恢复该分量 |
| 断线、失焦、最小化、Steam Overlay | 结束或取消手势、清除边沿；重连或恢复时不自动补点击 |

释放屏障要有故障退路，不能永久禁用游戏；但正常情况下也不能仅靠超时把仍按住的 RT 直接送回游戏。故障恢复的具体策略和提示在阶段一验证。Steam Overlay 不一定导致窗口失焦，须单独确认暂停信号；不得为了读取状态擅自重新初始化或关闭宿主的 Steam 生命周期。

## 保持 0.2.4 的网格规则

手柄只改变操作入口。自动恢复交付有效候选后自动采用并启用吸附，着色沿用现有开关；显式打开的临时相机选择器继续预览并等待采用，选择期间禁止画布落笔。不得重新引入旧版自动恢复的采用确认门槛。相机高度、翻转、源宽高比、stretch/contain/cover、切换来源、采用和取消都纳入手柄验收。

相机校验、手动恢复允许的范围、直接采用当前预览、关卡暂停、resize 清理、取消恢复旧网格、会话内几何与历史全部沿用。不能为了让方向键移动而跳过有效网格检查。已实现按屏幕方向选择相邻格；不新增相机方向自动推断。

## 实施阶段与验收门槛

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| 一：接入和隔离原型 | 设备快照、入口试验、实际游戏路径记录、进入/退出过滤 | 原生 Xbox 与 Steam 模拟均可读；绘画不驱动游戏；退出无卡键；入口无未解决副作用 |
| 二：基础操作闭环 | 虚拟光标、绘制/擦除、工具颜色、撤销重做、窗口操作 | 不拿鼠标完成打开、星标、编号、箭头、擦除、撤销、退出；拖动不穿透 |
| 三：0.2.4 全流程和设置 | 相机/网格/报告界面、手柄偏好与改键、断连/混用处理 | 待确认网格全程可操作；快捷键和设置兼容；必要操作不依赖键盘 |
| 四：独立预览包 | 独立版本标识、隔离测试包、验收记录 | 下列自动和实机测试达标；安装回滚可验证；既有发布资产不变 |

总体为中到高工作量，第一阶段的不确定性最高。先完成第一阶段再估算剩余工期；若实际走原生 Steam 动作或存在不可控的双路输入，应调整支持范围和接入方式，不能以“读到一个按钮”作为进入完成态的依据。

## 验证清单

自动测试重点是行为边界：

- 组合键先后顺序和组件消费、入口单次触发、扳机不同按下/释放阈值、按住与连发。
- 光标在不同 dt、尺寸和宽高比下的归一化位移、死区、极值/异常输入和边界。
- A 与 RT 互不穿透，界面拖动/画布手势跨边界，弹窗、改键和 inputSuppressed 期间不触发快捷动作。
- 断线、设备切换、回中屏障、源切换、Overlay 和窗口失焦，不产生重复点击或悬挂手势。
- 中立状态的 packet number、缓存查询、已有 Steam 挂接、递归/并发及故障恢复。
- 分组编号、擦除、撤销重做，以及网格预览/采用/取消/resize/关卡暂停原有规则。
- pad.* 设置往返、非法值回退、旧 key.* 加载，运行现有四套 C++ 测试。

最低实机矩阵包括：Xbox + Steam Input 关、Xbox + Steam Input 开、至少一种非 Xbox 手柄经 Steam 模拟，以及纯键鼠模拟模式。未知混合布局用于验证限制和降级，不列入首版无条件支持清单。

补测有线/无线、非零槽位、多手柄、运行中插拔、Steam Overlay、前后台切换、按住扳机退出、启动时未连接、Steam 初始化先后差异。每个受支持路径同时观察草稿纸响应和游戏动作，不能只看覆盖层指针会动。

代表输出尺寸为 1280×720、1920×1080、1920×1200、2560×1600、3440×1440、3840×2160、5120×1440，并加 1280×1024 和 640×360 的布局检查；覆盖 30/60/高刷新帧率及卡顿恢复。数值测试覆盖全部组合，实机使用代表组合并记录缺项，不把一台机器通过写成所有分辨率通过。

打包前运行适用的安装器、更新器和旧版升级回归，所有升级/卸载先在 work/ 隔离夹具完成。测试包准备好也不自动覆盖真实游戏安装。

## 交付判断

可以推进独立试验版，首要投入是实际输入路径与隔离原型。正式支持声明需要原生 Xbox 和 Steam 模拟两条路径的真实游戏验收；完整纯手柄闭环还必须包含无副作用入口、相机选择与网格确认、失焦/断连恢复。当前基础实现已进入独立 Preview 5 实机验收阶段，尚不构成全部实机路径通过。

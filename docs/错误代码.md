# 错误代码

更新日期：2026-10-29（Asia/Shanghai）。错误编号从 0.1.3 起提供，旧 0.1.2 安装包使用原提示。

## 反馈方式

报错以 `[SS-类别-编号]` 开头。反馈时保留完整编号和提示，附上发生操作、关卡、分辨率及是否刚切换地图/窗口。游戏目录内的 `StarSketch.log` 会记录相同网格错误编号和内部诊断。诊断增强版请提供启动版本标记，以及同一 `pid`、`grid_request` 的完整失败日志组（从报错首行到最后一条 `sample`），或直接提供日志文件；只截取首行会遗漏具体拒绝原因。

旧提示“数据定位未就绪，请重试或按 Shift+G 手动校准”合并了下面的 GRID-006、007、008、009；其中相机等待超时现在进一步分出 GRID-010。仅凭旧截图无法区分原因。

## 游戏数据网格

编号表示失败的检查位置，不一定能单独确定根因。普通游戏视角下点击“重新识别”可重试；失败期间暂停旧网格吸附及染色，当前本地 0.2.1 可使用“临时选择相机”，旧三点/四点入口已经移除。

| 编号 | 内部诊断名 | 含义及排查方向 |
| --- | --- | --- |
| SS-GRID-001 | unsupported_game_build | 游戏完整 SHA256 不匹配或校验失败。当前本地 0.2.1 改为单独的灰色兼容性提示，仍尝试识别与关卡监测；成功或失败不清除此提示，实际读取/布局/相机错误另行显示。旧版会停用自动读取。 |

| SS-GRID-003 | settings_array_unavailable | 关卡设置数组不可读或数量/容量校验失败。 |

| SS-GRID-005 | actor_layer_unavailable | 未取得有效角色高度层，且未设置高度覆盖。 |
| SS-GRID-006 | fresh_camera_frame_unavailable | 1.8 秒内没有取得有效的新相机帧，超时时仍有候选地址；候选不保证持续有效。 |

| SS-GRID-013 | auxiliary_camera_only | 本次只取得已知辅助用途的新视图，未取得可供自动识别的正常来源。最新独立兜底构建只在两种来源均无可用预览时才发出；若任一来源有可显示网格，转普通手动预览。辅助用途不能仅靠翻转认定正确，仍不自动采用。 |

| SS-GRID-099 | unknown_game_grid_error | 未分类的定位失败兜底，反馈完整日志。 |

方向校验检查相机向下观察、地面投影朝向和世界向上的屏幕方向；允许正常水平旋转，不限制某一网格步长必须朝屏幕上方。新增 `manual grid direction 20261026` 构建保留三态校验：正常新帧优先，只有方向不符的新帧可进入手动预览，其他失败不能借此放行。首次预览暂停吸附与染色，用户在“网格精调”中上下/左右翻转并“确认并记住”后采用。记忆按方向类别区分，只保存选项，不保存几何或改变已有标注；不自行翻转相机矩阵。没有可用预览时的 011 仍只说明本次曾发现异常候选，不能证明所有候选都异常。

2026-10-29 用户授权适当放宽识别：`camera recovery preview 20261029` 在自动等待结束后有可用候选时显示 015 预览，不再仅报 013/010。主视图 type=8 若只因辅助投影逆矩阵误差失败，可在误差不超过 1、`projection * view` 与主变换的逐项相对误差小于 0.025 时进入手动预览；主变换/逆、新帧、有限数值、方向、视口、地图、关卡与几何检查仍执行。该辅助逆矩阵不参与网格计算；完整自动校验仍使用原 0.025 阈值。失败日志保留原拒绝计数，`recovery` 行另列预览放宽次数和阈值。最终正确贴合仍需玩家检查，015 不表示已自动确认。

成功定位日志新增 `direction_category`、`manual_direction`、`direction_choice` 和 `direction_confirmed`；手动变更写入 `Grid direction` 日志。category 是方向判据的位组合：1=向下条件不符，2=地面朝向不符，4=世界向上条件不符；choice 的 1=左右翻转，2=上下翻转，可以组合。类别与选择不是相机身份或正确概率。未确认预览仍可能记录定位成功，因为几何已产生，是否启用吸附须看 `direction_confirmed`。

2026-10-26 本地修复构建的启动日志包含 `camera scan fix 20261026`。该最初构建只放行原尺寸和半分辨率；后续 0.2.1 的 `render modes fix 20261026` 构建进一步支持固定 720P/1080P/1440P/4K，包含内部渲染大于窗口的情况。尺寸仍须满足已知档位、宽高比和范围检查，不接受任意等比例尺寸。成功日志中的 `render=` 是相机内部视口，`output=` 是完整输出窗口，可直接对照二者。扫描按可读内存区和 64 KiB 块进行，跳过保护页和未提交区域，不再因整段栈读取失败或栈大于 8 MiB 丢弃整条线程。

GRID-006/010/011 的日志附加本次请求内累计扫描信息：`scans` 扫描次数、`threads` 发现的线程数、`stacks` 有效栈范围数、`bytes` 实际读取字节数、`unreadable` 跳过的不可读区域数、`read_failures` 分块读取失败次数、`viewport_matches` 尺寸匹配块数、`invalid` 其他校验失败块数、`orientation` 方向拒绝数、`valid` 有效候选数、`system_error` 最近一次系统错误/线程查询状态。计数包含重复扫描，不表示独立相机数量；保护页被正常跳过并不单独表示错误。反馈时提供本次启动标记、报错附近完整日志和输出/内部渲染设置；只有截图仍不能确定具体失败环节。

### 0.2.1 相机失败诊断增强

启动日志标记为 `StarSketch 0.2.1 | camera diagnostics 20261026`。诊断自动启用，无需修改配置。玩家界面和原有错误编号保持不变；细节在失败后逐行写入日志，各行重复同一个错误编号、`grid_request` 请求编号和 `pid` 进程编号，避免长文本被单行缓冲区截断。报错首行的 `utc` 是 UTC 时间；`elapsed_ms` 是本次定位耗时。

日志分为以下几类：

| 日志字段 | 说明 |
| --- | --- |
| `context` | 输出窗口尺寸、已验证游戏/关卡标志、逻辑行列、有效角色数量、是否覆盖高度、请求/选中高度和剩余候选数。尚未选中高度时 `selected_z=nan`。 |
| `scan` | 原有扫描汇总；包含重复扫描的累计计数。 |
| `sampling=background` | 2026-10-29 本地构建使用独立线程在定位/收集期间采样，不限于 Present 阶段。扫描间隔 50ms，候选轮询延迟循环使用 3/4/5ms；完成、取消或替换请求后停止。自动结果交付时仍核验关卡/管理器和 250ms 捕获寿命；已显示的手动预览继续直接采用。 |
| `scan_access` | 区分查询 API 缺失、线程快照/枚举/打开/查询、TEB 读取、异常栈范围、VirtualQuery 和分块读取失败；分别附 Win32 错误或 `query_ntstatus`，后者不是 Win32 错误号。保护页/未提交区是正常跳过；按页重试分别计入恢复/失败次数。 |
| `checks stage=scan` | 尺寸匹配块的完整相机校验结果。`accepted` 表示通过该阶段，不保证它是主相机或新帧。 |
| `checks stage=cache` / `poll` | 本次请求对旧候选的复用检查，以及等待时的候选复读结果；`read_failure` 与扫描内存块失败分别统计。 |
| `checks stage=fresh` | 候选通过相机校验后，帧号和时间是否满足新鲜度要求。 |
| `checks stage=viewport_probe` | 尺寸不匹配、但通过有限结构探查的近似相机样本数，仅作为诊断线索；不会加入定位候选，也不会启用吸附。 |
| `viewport_probe` | 每次扫描最多执行 64 次深入尺寸探查；记录实际检查数和预算用尽后跳过数。`skipped_budget` 非零时，探查结果不完整。 |
| `limits` | 本构建实际使用的数值范围、尺寸档位、方向、矩阵、新帧等阈值。 |
| `sample` | 每个拒绝原因最多一条代表样本，每次请求最多 6 条；优先保留尺寸、读取、新帧和矩阵问题。包含内部 `render` 尺寸、帧号/时间、方向长度平方、地图量、两组逆矩阵误差、投影深度、方向判据及首个非法字段。浮点关键值使用 9 位有效数字，便于比较临界值。 |

具体拒绝原因如下，表示候选遇到的首个失败检查：

| 原因 | 含义 |
| --- | --- |
| `transform_values` / `camera_values` | 变换矩阵或相机字段非有限，或绝对值超过 1e7；`bad_index` 为 Viewpoint_Params 浮点数组下标，`bad_value` 为当时值。 |
| `viewport` | 内部视口与允许的输出尺寸、宽高比或渲染档位不匹配；对照样本 `render` 与上下文 `output`。 |
| `direction_norm` | `direction_norm2`（方向长度平方）不在 0.94～1.06。 |
| `frame_index` / `camera_time` | 帧号为零，或相机时间为负数；非有限时间会先归入 `camera_values`。 |
| `map_amount` | 地图量非有限，或大于 0.05；地图视角仍不支持。 |
| `transform_inverse` / `projection_inverse` | 对应逆矩阵误差达到或超过 0.025。 |
| `forward_depth` | 相机前向射线的投影深度非有限，或不大于 0.1。 |
| `orientation` | 视角方向、地面投影朝向或世界向上方向不符合支持条件；样本含 `direction_z`、`handedness`、`world_up`。 |
| `read_failure` | 候选地址复读失败，附 `read_error`；此时 `has_camera=0`，其他相机样本字段不代表实际读到的值。 |
| `frame_static` / `frame_jump` | 帧号没有前进，或无符号前进量超过 2000；可能涉及旧副本、帧号重置或来源问题。 |
| `time_reversed` / `time_jump` | 相机时间差为负，或超过 5 秒。只有 `stage=fresh` 样本的 `advance` / `seconds` 表示实际新帧差值。 |

若 `stacks=0` 或 `bytes=0`，优先看 `scan_access`。若有有效候选但持续 `frame_static`，优先排查数据来源是否更新。若只有 `viewport_probe` 留下样本，优先对照内部/输出尺寸。以上都是排查线索：线程栈可能包含其他视图和旧副本，计数不是不同相机数，单条代表样本不能直接证明根因。日志只保存计数和有限数值，不保存完整矩阵、原始内存块、画面、草稿或校准几何；尺寸探查不更改识别阈值和最终采用规则。

### 2026-10-27 本地相机采集修复

启动标记增加 `camera capture fix 20261027`。样本行新增 `source_type`（偏移 904 的原始 uint32）与 `source=main/reflection/auxiliary/unknown` 提示；它们不放宽数值、矩阵、视口、地图及新帧检查。成功日志也附这些字段和 `capture=scan/poll`、`capture_age_ms`。

失败组新增 `capture` 行：`rounds` 为本请求观察轮数，`early` 为在本帧 Win32/ImGui/DX12 工作前的采集次数，`history` 为有界会话基线数，`scan_fresh`/`poll_fresh` 为扫描快照/地址复读取得的新帧数，`moved_fresh` 为同用途、同投影在新临时地址取得的新帧数，`auxiliary_fresh` 为其中的已知辅助用途数量。均包含重复观察，不表示独立相机数或正确概率。

自动与临时请求都保留最多 512 个请求内基线。扫描中取得完整有效新帧时立即复制到堆内存，避免随后栈覆盖；同轮扫到两个旧副本不能建立新鲜度。自动投影只消费最多 250ms 前采集的完整副本并复核关卡身份，超龄需重新采集；这与用户手动采用预览后的会话网格保留无关。诊断仍最多六条标量样本，不记录完整矩阵、原始内存或标注。

仅 `source_type=5` 反射用途额外允许“已支持场景内部尺寸的 1/2、1/4”尺寸关系，保留原像素容差和最小尺寸。它可以解释相对输出的 1/6、1/8、1/12 等关系，使受保护的新反射帧能进入手动列表或明确报 013；不会把这些比例加入其他用途的通用白名单，也不会自动采用反射。

## 错误反馈辅助（本地 2026-10-29）

报错旁的“汇报错误”引导先用临时选择相机检查，再由“打开游戏目录并复制邮箱”执行两项本地操作。不调用邮件/GitHub 提交接口，也不会读取或上传日志。

| 编号 | 内部诊断名 | 含义 |
| --- | --- | --- |
| SS-REPORT-001 | report_folder_unavailable | 读取实际游戏目录或使用系统资源管理器打开失败；手动打开沉星之序安装目录，找到 StarSketch.log。日志附 `folder_error`。 |
| SS-REPORT-002 | report_clipboard_unavailable | 复制邮箱失败，例如系统剪贴板暂被占用；重试或手动输入 xlwpy@qq.com。日志附 `clipboard_error`。 |
| SS-REPORT-003 | report_diagnostics_unavailable | 诊断信息生成或复制失败，含任务启动失败/剪贴板占用；可重试，或直接发日志并说明环境。日志附 `clipboard_error`，此值也可能是任务启动错误。 |

两项独立执行，失败提示保留另一项是否成功；不会把部分成功写成两项都成功。成功日志为 `game_folder_opened=1 email_copied=1`。提示、工作结果及原错误快照只在本次会话内保留。

“一键复制诊断信息”单独复制当前分辨率/窗口、系统/显卡/驱动、插件与关卡状态、原错误和当前状态。它与打开目录/复制邮箱共用串行短时任务，忙时两个按钮都禁用；仅复制成功才记录 `diagnostics_copied=1`，不将诊断全文写入日志。系统字段在后台读取，显卡匹配实际 D3D12 设备的 LUID；无权限/不支持的字段显示未取得。没有上传、邮件发送或绘画/网格序列化。

## 维护规则

- 新增玩家可见错误必须在提示最前面放稳定编号，相关日志使用相同编号。成功和正常等待提示无需错误编号。
- 编号不因文案或代码顺序调整而变化，不得挪用旧编号表达其他原因。
- 运行时网格错误使用 `src/errors.hpp` 的类型与注册表；在检测失败处设置类型，界面和日志共享格式。
- 同步维护本表，并验证失败状态、重试清除错误编号、手动校准接管及未知异常兜底。

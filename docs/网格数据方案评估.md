# 网格数据方案评估与实现

日期：2026-10-22（Asia/Shanghai）
状态：0.1.1 已实现并安装实机验证。支持本机 r67271；当前验证小关卡为 torc_blocked，3840×2160。

## 结论

网格可以通过游戏数据直接定位。运行时读取逻辑网格、角色高度层和主视图投影矩阵，不需要寻找截图中的地砖纹理。实机重启后按 G 自动对齐，T 染色、图钉和箭头吸附已验证。手动校准仍保留。

这不是全部关卡与像素误差的全面测评：当前实际画面对照来自一个小关卡；数学投影误差检查只证明转换代数一致，不能把它当作屏幕贴合误差。多角色分层、其他关卡、分辨率及兼容模组组合仍需覆盖。

## 原图像算法的问题

src/grid.hpp 使用缩小画面的边缘、近水平/竖直方向和等距周期，输出仿射网格。装饰纹样、灯光、砖缝和透视容易造成半格、双格及相位错判。手动四点模型支持透视，不会让旧自动算法自动具备此能力。0.1.1 游戏运行路径已停止调用该算法；只保留诊断和测试。

- SHA256：0ae10a513dae25286fe93d0db4fa8a2df9a473bc07e1734e12bc1ad30166db1c。

- Jai 反射：711 结构、261 枚举。Settings、Camera_Control 及选取的玩法实体无未解析成员。
- Settings 51380225：12×9，108 个逻辑格，corner=(-1,2,-1)，squares_z=3。这是逻辑范围，不能当作可见地板数量或可通行性。
- 静态 Camera_Control 的初始姿态可读，但运行时镜头会摆动，不能直接替代当前相机。
- 运行时 Settings.ground_z0=0、underground_z0=-10、skyground_z0=10；当前 Guy 坐标 (5,5,1)。地面标注采用角色所在逻辑高度 z=1，并通过游戏地砖叠加对照。不能将 Settings.ground_z0 直接当作格心平面高度。

## 主视图矩阵验证

Viewpoint_Params 为 960 字节：transform 0、inverse_transform 64、view 640、inverse_projection 704、projection 768、origin 832、time 844、direction 848、inverse_viewport 864、frame_index 900、map_amount 940。

先从外部仅以 PROCESS_QUERY_INFORMATION|PROCESS_VM_READ 读取；找到会随帧更新的线程栈副本。旧堆内常量缓冲副本多数不更新，不能当作当前相机。栈范围诊断扫描约 2.4 MiB，约 40ms；这是外部诊断的测量，不是插件的性能基准。

主世界实际按 Tab 切入完整地图并返回：斜视 origin 约 (41.999,112.441,21.400)，地图约 (79.037,75.993,500)，direction=(0,0,-1)、map_amount=1；返回后恢复斜视矩阵。地图瞬态栈扫描有一次未命中；已知地址的只读原始快照确认了变化。该测试证实数据来源会跟随真实镜头，不代表支持地图模式。草稿纸读取器拒绝 map_amount>0.05。

进入小关卡后，origin 恢复到约 (5.15,-0.78,17.60)。以行优先 M 计算 clip=M*[x,y,z,1]，经过透视除法和视口变换后得到格心；将平面投影精确转换为现有 Grid 的 origin/u/v/px/py。近处格距大于远处，未用等距仿射近似。

## 0.1.1 读取路径与保护

- src/game_grid.cpp 首次校验游戏磁盘文件完整 SHA256；不匹配就停用自动数据读取。
- 仅对这个已验证版本：主模块 RVA 0xb69600 读当前 Entity_Manager 指针；manager+0xdd0 为 Settings 动态指针数组，manager+0x920 为 Guy 动态指针数组。
- 验证数组数量/容量、对象 manager 归属、Jai 类型标签/名称/结构大小、逻辑格数量和浮点范围。每次定位重新读当前对象，不保存绝对运行时地址。
- 从本进程的线程栈发现相机，验证逆矩阵、视口、方向、非地图状态，并等待 frame_index 前进后才采用，拒绝旧帧数据。缓存的栈地址在下一次定位前重新验证。
- 高度默认取投影位置最接近屏幕中心的有效 Guy.z；可在网格精调中覆盖，或恢复“使用角色所在层”。此策略不等于已确定当前被操控角色，多角色分层需更多测试。
- G/T 首次使用、重新识别及再次进入已有数据网格的绘画模式时定位。绘画期间冻结；标记始终保存屏幕坐标。手动调整过的几何网格不在 E 再次进入时自动覆盖。
- 指针读取通过 ReadProcessMemory(GetCurrentProcess())，不写玩法数据。无外置进程、无需管理员权限、不修改原始游戏资源。
- 数据失效/版本不匹配时保留几何预览；如果旧结果来自自动数据定位，则取消其可信状态并暂停吸附/染色，提供重试、主动采用或手动校准。用户已确认的手动几何结果继续保留。不自动采用低可信图像结果。定位期间更换 manager 会拒绝本次结果。
